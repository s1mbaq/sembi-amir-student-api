# Подготовка к защите Sembi Amir

Краткие ответы по темам из задания. Повторяющиеся вопросы объединены.

## 1. Что такое Docker?

Платформа для сборки образов и запуска приложений в изолированных контейнерах с общим ядром ОС. Помогает повторять среду разработки и CI.

## 2. Что делает git commit?

Создаёт снимок staging area в локальном репозитории с автором, временем и сообщением. На GitHub отправляет git push.

## 3. Для чего #!/bin/bash?

Shebang указывает интерпретатор при прямом запуске исполняемого скрипта.

## 4. Что такое Jenkinsfile?

Версионируемый файл описания pipeline. В работе содержит Checkout, Build, Test, Docker Build, Verify.

## 5. Образ и контейнер

Образ — шаблон слоёв файловой системы и метаданных. Контейнер — запущенный или остановленный экземпляр образа со своим записываемым слоем.

## 6. pwd

Показывает абсолютный путь текущей рабочей директории.

## 7. Continuous Integration

Регулярная интеграция изменений в репозиторий с автоматической сборкой и тестами.

## 8. Git branch

Именованный указатель на последовательность коммитов. Изолирует разработку функции до объединения с основной веткой.

## 9. RUN и CMD

RUN выполняется при сборке образа и создаёт слой. CMD задаёт стандартную команду или аргументы запуска контейнера; docker run может их переопределить.

## 10. Дисковое пространство

df -h показывает занятое и доступное место файловых систем; du -sh DIR показывает размер каталога.

## 11. Git и GitHub

Git — распределённая система контроля версий; GitHub — сервис размещения репозиториев с совместной работой.

## 12. Docker Compose

Описывает приложение, PostgreSQL, сеть и volume в YAML и запускает их согласованно.

## 13. chmod

Меняет права доступа. chmod 744 означает rwxr--r--; chmod +x добавляет разрешение исполнения.

## 14. Checkout stage

Получает исходники нужного Git-коммита в workspace агента, обеспечивая сборку конкретной версии.

## 15. > и >>

> создаёт или очищает файл и записывает вывод; >> создаёт файл при отсутствии и дописывает в конец.

## 16. Merge conflict

Git не может автоматически совместить несовместимые изменения, например одной строки. Нужно вручную выбрать итоговый текст, удалить маркеры, выполнить git add и git commit.

## 17. Docker volume

Хранилище отдельно от жизненного цикла контейнера. Сохраняет данные PostgreSQL при пересоздании контейнера. docker compose down -v удаляет volume.

## 18. Delivery и Deployment

Continuous Delivery готовит проверенный результат к выпуску, который можно подтвердить вручную; Continuous Deployment автоматически выпускает прошедшие проверки изменения.

## 19. FROM

Задаёт базовый образ стадии. Несколько FROM позволяют отделить сборку на JDK от исполнения на JRE.

## 20. Jenkins job

Настройка повторяемой работы: источник SCM, pipeline и триггеры. В работе Sembi_Amir_Student_API.

## 21. fetch и pull

fetch загружает remote refs и объекты, не объединяя их с текущей веткой; pull выполняет fetch, затем merge или rebase согласно настройкам.

## 22. Последние пять строк

tail -n 5 logs/Sembi_Amir_system_report.log.

## 23. Multi-stage build

Один Dockerfile собирает JAR в стадии JDK и копирует только JAR в стадию JRE. Финальный образ не содержит исходники и Gradle.

## 24. Working tree, staging, repository

Working tree — редактируемые файлы, staging/index — подготовленный следующий снимок, repository — сохранённые коммиты и объекты Git.

## 25. Зачем тесты перед выпуском?

Чтобы обнаружить регрессии до передачи пользователям; неуспешные тесты должны остановить последующие стадии.

## 26. free -h

Показывает RAM, доступную память, buffers/cache и swap в удобных единицах. Available полезнее одного показателя free.

## 27. WORKDIR

Устанавливает рабочий каталог для следующих RUN/COPY/CMD/ENTRYPOINT в данной стадии.

## 28. merge и rebase

merge объединяет историю и при необходимости создаёт merge-коммит; rebase переносит коммиты на новую основу, меняя их идентификаторы. Общую опубликованную историю без согласования не переписывают.

## 29. Private GitHub в Jenkins

Создать Jenkins Credential для токена или SSH-ключа с нужными правами и выбрать credentialsId в SCM. Не вставлять пароль в URL или Jenkinsfile.

## 30. Процессы Linux

Экземпляры выполняемых программ. ps -ef, ps aux, top; pgrep -af java ищет Java. Docker Compose top app показывает процесс контейнера.

## 31. docker build

Собирает образ из Dockerfile и контекста; -t задаёт имя и тег.

## 32. .gitignore

Исключает незатреканные совпадающие файлы из обычного git add. Уже закоммиченные секреты сам не удаляет.

## 33. Controller и agent

Controller управляет конфигурацией, очередью и историей; agent выполняет шаги в workspace. Здесь controller имеет 0 executors, выделенный agent — 1.

## 34. 755

Владелец rwx, группа r-x, остальные r-x. Для системного скрипта в задании требуется 744: группа и остальные только читают.

## 35. Почему db, а не localhost?

Внутри app localhost — сам контейнер приложения. DNS сети Compose разрешает имя сервиса db в адрес PostgreSQL.

## 36. git status

Показывает текущую ветку, staged/unstaged изменения, untracked файлы и состояние merge.

## 37. Build trigger и webhook

Триггер запускает job по событию или расписанию. GitHub webhook посылает HTTP-событие Jenkins; polling проверяет изменения SCM по расписанию.

## 38. Аргументы Bash

$1, $2 — позиционные аргументы; "$@" — все аргументы с сохранением границ; $# — количество.

## 39. COPY и ADD

COPY копирует файлы из контекста или стадии. ADD дополнительно поддерживает автоматическую распаковку локальных tar и удалённые источники. Для JAR достаточно COPY.

## 40. docker stop и rm

stop останавливает контейнер, сохраняя его; rm удаляет контейнер. Данные в volume сохраняются, пока volume отдельно не удалён.

## 41. Почему нельзя коммитить пароли?

Публичный репозиторий и Git-история сохраняют секреты. Удаления файла недостаточно: нужно отозвать секрет, затем исправить историю по согласованному процессу.

## 42. Ошибка стадии Jenkins

Шаг sh с ненулевым кодом завершения по умолчанию приводит к FAILURE и пропуску следующих обычных стадий. post always может выполнить публикацию результатов.

## 43. Скрытые файлы

ls -la показывает имена, начинающиеся с точки, и права доступа.

## 44. Разрешение README conflict

git status, открыть README, объединить нужный текст, убрать <<<<<<<, =======, >>>>>>>, выполнить git add README.md и git commit.

## 45. Health check PostgreSQL

pg_isready определяет, принимает ли сервер соединения. depends_on condition service_healthy задерживает старт app до готовности db, но не заменяет проверку реального API.

## 46. git push

Отправляет локальные refs и необходимые объекты в remote; ветки и теги нужно публиковать явно.

## 47. Declarative и Scripted Pipeline

Declarative использует блок pipeline с заданной структурой stages/steps/post; Scripted описывает более свободный Groovy-код с node и stage.

## 48. Поиск и завершение PID

pgrep -af NAME или ps -ef; kill PID отправляет SIGTERM. kill -9 PID — принудительное завершение, когда корректное завершение не помогает.

## 49. EXPOSE

Документирует порт приложения в образе. Сам порт на хосте не публикует: для этого ports или docker run -p.

## 50. Jenkins Credentials

Хранилище секретов Jenkins. Шаг получает секрет по credential ID, а не из исходного кода. Требуется ограничивать доступ к job и агентам.

## 51. Абсолютный и относительный путь

Абсолютный начинается от корня, например /home/amir/project; относительный вычисляется от текущего каталога, например scripts/report.sh.

## 52. Новая ветка

git switch -c feature/sembi-amir-crud создаёт ветку и переключается на неё.

## 53. Почему агенту нужен Docker?

Docker CLI отправляет запросы Docker daemon. В работе агент имеет CLI и доступ к локальному socket; одного JDK недостаточно для docker build.

## 54. Network и volume

Network связывает контейнеры и обеспечивает DNS сервисов; volume хранит данные независимо от контейнеров.

## 55. Поиск слова

grep Sembi FILE; grep -n показывает номера строк, grep -i игнорирует регистр.

## 56. git init

Создаёт метаданные репозитория .git в текущем каталоге; git init -b main выбирает начальную ветку main.

## 57. Логи Docker

docker logs CONTAINER; docker compose logs --tail 40 app; -f следит за новыми строками.

## 58. Как остановить pipeline на тестах?

Выполнить sh ./gradlew test без подавления exit code. Не использовать || true и не игнорировать результат через catchError.

## 59. mkdir и mkdir -p

mkdir создаёт каталог, но требует существующий родитель и обычно ошибается при наличии цели. -p создаёт отсутствующих родителей и допускает существующий каталог.

## 60. Git tag

Именует конкретный коммит версии. Аннотированный tag дополнительно содержит автора и сообщение. В работе v1.0-37693.

## 61. Передача DB credentials

Локальный .env подставляет переменные окружения Compose. В CI использовать secret manager/Jenkins Credentials. Не включать пароль в JAR, Dockerfile или Git.

## 62. Build stage

Компилирует приложение и собирает JAR через ./gradlew clean assemble; Test отдельно запускает ./gradlew test.

## 63. cp и mv

cp копирует файл, сохраняя исходник; mv перемещает или переименовывает.

## 64. git add

Помещает текущую версию выбранных изменений в index/staging area будущего коммита.

## 65. Jenkins console output

Причина запуска, checkout и commit, имя студента, команды, ошибки компиляции/тестов, результат создания и проверки образа, итог SUCCESS/FAILURE.

## 66. Проброс 8080

docker run --rm -p 127.0.0.1:8080:8080 IMAGE. В этой работе выбран свободный персональный порт 8093.

## 67. Linux в DevOps

Ядро ОС и основанные на нём системы, широко используемые для серверов и контейнеров благодаря инструментам автоматизации, управлению процессами и открытой экосистеме.

## 68. Commit и tag

Commit хранит снимок и связь с родителями; tag даёт имя выбранному коммиту.

## 69. docker-compose.yml

Описывает app и db, image/build, переменные, порты, healthcheck, named volume и выделенную сеть.

## 70. Неуспешный Gradle в Jenkins

Найти первую причину в Console Output, изучить test report, воспроизвести ./gradlew test --stacktrace или build --stacktrace на том же JDK и коммите, исправить и повторить.

## 71. Пустой файл

touch FILE создаёт пустой файл, если он отсутствует; существующий файл не очищает. : > FILE очищает содержимое.

## 72. Осмысленные commit messages

Показывают, что изменилось и зачем, упрощают review, поиск регрессий и защиту индивидуальной работы.

## 73. Test stage

Выполняет автоматические проверки приложения; при ошибке образ в следующих стадиях не собирается.

## 74. Команда внутри контейнера

docker compose exec -T app java -version или docker exec CONTAINER COMMAND.

## 75. Поиск фамилии в лог

grep Sembi logs/Sembi_Amir_system_report.log > logs/Sembi_Amir_log_analysis.txt.

## 76. Локальный код отличается от GitHub

Сначала git status и сохранение локальной работы коммитом или stash, затем git fetch, просмотр git log --graph --all и git diff main origin/main; выбрать merge/rebase, разрешить конфликты, проверить тесты и push. Не начинать с reset --hard.

## 77. Spring Boot не подключается к PostgreSQL

Проверить docker compose ps и health db, logs app/db, DB_URL с db:5432, одинаковые DB_USER/DB_PASSWORD и общую сеть. Старый volume хранит прежний пароль: изменение POSTGRES_PASSWORD не меняет пароль существующей БД автоматически.

## 78. Jenkins Build проходит, Docker Build падает

Найти ошибку стадии; проверить docker version/info от имени агента, socket/TLS-права, Dockerfile и контекст, доступ к registry, свободное место и наличие ожидаемого JAR. Повторить команду на том же агенте после исправления.
